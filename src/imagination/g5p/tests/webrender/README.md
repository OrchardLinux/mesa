# WebRender compiler candidates

These are focused fixtures for primitive-local derivative analysis, mixed-bank
vertex texture moves, bank1 math bridges, position W coefficient reservation,
and the transparent-black identity of selected general blend equations.
They do not qualify the complete Firefox compositor.

Compile compiler.c with the actual driver's flags and archives. Its interface
matches linux-a9 tools/g5p-1b-dgl/compiler.c. Extra keys 7/8 test additive and
multiplicative transparent-black identities; key9 now tests a nonidentity general-blend hardware kill. The loop-carried varying_*.frag controls in ../derivatives must still
refuse, including varying loop exits. flat-derivative.frag must compile.
Set PVR_G5P_VS_BANK0_FIRST=1 to exercise bank0-fetch.vert/bank0-rcp.vert without
requiring incidental register pressure. This is an existing offline test hook.

numeric.c uses independent analytic per-pixel oracles for six cases. Compile
with cc -O1 numeric.c -o webrender-numeric -lEGL -lGLESv2 -lm. Run in surfaceless
EGL on the device, first with default allocation, then with
PVR_G5P_VS_BANK0_FIRST=1. Both must print WR-NUMERIC RESULT PASS cases=6 failed=0
reference=0 with no driver refusal/fault. --reference permits a software GL
renderer solely to validate the oracle; it is not G5P evidence. A fake node's
zero readback must FAIL. Depth/stencil effects of discarded fragments and
nonidentity blend equations remain outside this colour-only lowering.

The pinned unoptimized Firefox 158 GLES census is generated by linux-a9
scripts/gpu/firefox/webrender-corpus.py. It currently exposes additional register
pressure after these guards clear; don't label a census PASS based on process
exit zero or glGetError alone. Zink can log a failed pipeline and return GL_NO_ERROR.


WR3: position W planning queries NIR uses before backend liveness; all four
position-w fixtures must report w_set=1. The safety parent refused the
no-smooth interface; the subsequent fix is hardware-numeric pending.
branch-invariant-derivative.frag must compile with its derivative before the
varying branch. Loop-carried sources, varying exits/continues and mutable
memory remain negative controls. No helper-execution mode is inferred from
Apple's divergent derivative programs.

wr3-numeric.c adds seven CPU pixel/DS visibility checks, dual-numeric.c two
spatially varying source1 equations. z-numeric.c is a two-range analytic
oracle for the still-refused Z boundary, not an enabled feature. All accept
--reference solely to validate expectations with a software rasterizer.
Actual G5P pixels remain pending. General blend kills use the driver's
existing PUNCH_THROUGH ISP rule and one merged kill token; TRANSLUCENT is
never substituted for a shader that retains a real kill.

Branch-local UBO/descriptor reads must not move across a bounds guard, even
though the resource is immutable. varying_guarded_ubo.frag must retain the
named divergent-derivative refusal. Already-dominating loads are unchanged.
